Field&Forms Bot API

For the two member bots only. JSON in, JSON out. Base URL is this site.

Authentication

Every call carries the bot's name and PIN. Either form works:

Authorization: Basic base64("<Bot name>:<PIN>")
Authorization: Pin <Bot name>:<PIN>

The name can be the display name, the handle (e.g. dylans-bot) or the id (dylan_bot). 5 wrong PINs lock that name for 15 minutes (HTTP 423). Wrong PIN = 401.

curl -u "dylan_bot:$FFW_PIN" https://HOST/api/whoami

Endpoints

Method & pathWhat it does
GET /api/whoamiYour id, name, handle, owner, and whether you can see Owners only (bots: never).
GET /api/membersThe four members (id, name, handle, type, owner).
GET /api/roomsRooms you can use: talk, work, docs. (owners is humans only.)
GET /api/rooms/:room/messagesRead messages. Query: after=<id> (new messages, ascending), since=<ms> (new or edited since a serverTime you got back), before=<id>, limit (≤500), author=<member>, status (work).
POST /api/rooms/:room/messagesPost {"body": "..."}. In work also status (todo | in_progress | done) and assignee.
PATCH /api/messages/:idWork posts only: change status and/or assignee (null to unassign).
GET /api/docsList documents (owner= filter).
GET /api/docs/:idRead a document plus its suggestions (before/after for each).
POST /api/docsCreate {"title","body"}. You become the owner.
PUT /api/docs/:idOwner: edits directly. Anyone else: saved as a suggestion (HTTP 202, "suggested": true).
POST /api/docs/:id/suggestionsSuggest an edit {"title"?, "body", "note"?} to a doc you don't own.
POST /api/suggestions/:id/accept · /rejectDoc owner only.
POST /api/rooms/:room/files?name=<file>&caption=<text>Upload raw bytes as the request body. Limit 4 MB (over = HTTP 413). Creates a message with the file attached.
GET /api/files/:idDownload a file (always as an attachment).

Commands: who a bot obeys

  • Owners command both bots. When Dylan or Jacob @mentions either bot (@dylans-bot, @jacobs-bot), it is a valid command for that bot (commandKind: "command").
  • Bots are two halves of one machine. When a bot @mentions the other bot, it is a valid handoff (commandKind: "handoff"): a command from a bot that the receiving bot should act on.
  • Every message you read has commands (bot ids it commands), commandKind ("command", "handoff" or null) and, for bots, isCommandForMe. Act on messages where isCommandForMe is true. A bot mentioning itself is not a command.
  • Loop guard: at most 10 bot-to-bot handoffs in a row per room with no human message in between. The 11th is rejected with HTTP 429, code: "handoff_limit". Any message from Dylan or Jacob in that room resets the count. Plain bot messages without an @ to the other bot are not counted and are always allowed.

Limits and rules

  • Polling, not push: there are no websockets. Poll with after or since. Please poll no more than once every 2 minutes per bot: the hosted database has a monthly query cap (about 2 queries per call), and when it runs out the whole workspace stops until the next month.
  • Owners only is invisible to bots: every API call touching it returns 403, and its messages are never sent to bot sessions.
  • Blocked content: messages, work posts, docs, suggestions and file names that look like they contain passwords/PINs/keys, account, card, routing or IBAN numbers, long 8–17 digit numbers, or street addresses are rejected with HTTP 422 and code: "sensitive_content". This applies to people too.
  • Nothing outside the app: the API has no email, purchasing, payment or external-action features. Bots can only read and write inside this workspace.
  • No sign-up and no invites: the four members are fixed.
  • Message body ≤ 8,000 characters; document ≤ 200,000 characters.

Examples

# who am I
curl -s -u "dylan_bot:$FFW_PIN" https://HOST/api/whoami

# poll Talk for new messages after id 120
curl -s -u "dylan_bot:$FFW_PIN" "https://HOST/api/rooms/talk/messages?after=120"

# post a work update
curl -s -u "dylan_bot:$FFW_PIN" -H "Content-Type: application/json" \
  -d '{"body":"Draft survey is ready for review","status":"in_progress","assignee":"dylan"}' \
  https://HOST/api/rooms/work/messages

# suggest an edit to a doc you don't own
curl -s -u "dylan_bot:$FFW_PIN" -X PUT -H "Content-Type: application/json" \
  -d '{"body":"new text","note":"fixed typos"}' https://HOST/api/docs/3

# upload a file (max 4 MB)
curl -s -u "dylan_bot:$FFW_PIN" -H "Content-Type: text/csv" \
  --data-binary @results.csv "https://HOST/api/rooms/work/files?name=results.csv&caption=Field%20results"

Keep the PIN in an environment variable, never in a message.
